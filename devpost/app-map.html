How acu-primer fits together

A teacher turns book pages into short lessons with Claude, reviews each one by playing it, and signs it off. Students play the signed-off lessons, get help aimed at each wrong answer, and the teacher sees each student's path. This page is a guide to where that lives in the code.

The main pieces

The player

src/app/player/. The student side: subjects, chapters, one module per screen, checks, hints, explorations. Works offline once a chapter is opened.

The author side

src/app/author/. Start from a book, Draft lessons, review by playing, sign-off, the student log.

The Worker

src/worker/. The API on Cloudflare Workers: routes/, the Claude calls in claude.ts, the D1 queries in db.ts.

Shared rules

src/shared/. Code both sides use: the lesson schema, grading, the hint flow, review rules, book plans.

One action, followed through the code

Choosing a book on Start from a book, until its chapters show up as a plan to create. Nothing here calls Claude when the PDF's bookmarks list the sections.

A reference route, three stops

Not toured together yet: a route to follow when you want to. Run the app (below), open Start from a book, choose a PDF, and read along.

  1. src/app/author/BookStart.svelte, search async function choose. Runs when you pick a file: it reads the PDF in the browser with readBook, makes the plan with planFromOutline, and only when no chapter has sections asks Claude for the contents (readContentsPages).

  2. src/app/lib/pdfOutline.ts, readBook, and src/shared/bookPlan.ts, planFromOutline. readBook refuses an encrypted PDF (its bookmarks and pages can't be read; cutPages in pdfPages.ts has the same guard, so a draft can't send blank pages). In planFromOutline: isPart and holdsChapters flatten parts ("Part I", "I Proofs"), NOT_A_LESSON leaves out exercises and "Problem 1.1", and tiny unticks short items with no sections.
  3. tests/bookPlan.test.ts, the test "flattens parts numbered with Roman numerals…". A small copy of a real book's bookmark shape (MIT's Mathematics for Computer Science) with the expected chapters written out, so a later change can't bring the parts back unnoticed. npm test runs it.

A practice to reuse

Check the symptom against what's in front of you, then follow the evidence before changing anything. On Oct 25, Start from a book said Claude found no table of contents in MIT's Mathematics for Computer Science, though the contents are plain on page 3. That mismatch, noticed while using the app, was the lead. Reading the bookmarks gave garbage titles with no pages, the pages cut out for Claude came out blank, and the file had an /Encrypt entry: the PDF was encrypted, and Claude had been sent empty pages. The fix went where the cause was (readBook and cutPages refuse encrypted PDFs) instead of into the prompt, and the planner fixes the unlocked copy then revealed went in with a test that uses the book's real shape.

How the work was split, for the record: Isaac ran the app (locally, deployed, on a phone), reported what was broken or confusing, and made the direction and scope calls; Claude wrote the code and the checks. The same split works on another project when every report names what was expected and what happened instead, and every fix comes with a check that would have caught it.
