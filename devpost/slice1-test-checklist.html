Code review notes

nothing fixed yet; confirm or dismiss each

I re-read the slice 1 code against checklist.md slice 1 and spec.md. Each item below is something I think is buggy or incomplete. Some of them may be the bugs you remember. Set each one to confirmed or dismissed after you try it. Confirmed items get fixed before the deploy, unless you say they can wait.

Blocks the deploy

R1 The D1 database id is a placeholderwrangler.jsonc:17 has "database_id": "00000000-0000-0000-0000-000000000000". Local dev ignores it, but npm run db:migrate:remote and npm run deploy will fail until it holds the id from npx wrangler d1 create acu-primer. Section 05 covers it. How to see it: it's not visible in the browser. Open the file.

Likely bugs in the player

R2 A module only counts as done after you press Continuesrc/app/player/ModuleView.svelte:41-42 saves progress inside next(). If you answer a check right and then press Overview or reload, that module isn't saved. How to see it: start fresh, answer module 1 right, press Overview. The count says 0 / 6, and Continue takes you back to module 1.
R3 "Not quite" stays on screen after you change your answersrc/app/player/ModuleView.svelte:75-76 only clears result when you press Check again. How to see it: on module 1, pick option A and press Check. Then pick option B without pressing Check. The "Not quite" line is still there under your new pick.
fixed Oct 9R4 The browser's Back button leaves the courseMoving between the overview and modules doesn't add browser history (src/app/player/Player.svelte:62-88 switches screens with state only). How to see it: open a module, then press the browser's Back button. You leave /c/openintro-sampling entirely, instead of going back to the overview. On a phone, that's the swipe back.
R5 The top progress bar is ahead of the overview countsrc/app/player/ModuleView.svelte:57 fills the bar to (index + 1) / total. On module 1 it's already a sixth full, while the overview says 0 / 6. How to see it: start fresh and look at the thin bar on module 1. It could be fine as "you're on module 1 of 6". Your call.
R6 A comma is read as a decimal pointsrc/app/player/checks/NumberInput.svelte:11 turns 0,86 into 0.86, which helps people who write decimals with a comma. But 1,000 becomes 1. The fixture never asks for a big number, so slice 1 can't break on this. Later lessons could. How to see it: on module 2, type 0,86. It says Right.
R7 The empty-course note comes after you type your namesrc/app/player/Player.svelte:69 asks for a name first, and only then does CourseOverview.svelte:39-40 say "Nothing is ready in this course yet." The PRD says only that the note appears. Making someone type a name to learn there's nothing there is a small annoyance. How to see it: step m10 in section 04.
R8 A course address with capitals shows the home pagesrc/app/App.svelte:5 only matches lowercase letters, digits and dashes. How to see it: open http://localhost:5173/c/OpenIntro-Sampling. You get the acu-primer home page, not "Can't open this course". /c/nope shows the error correctly.

By design, but worth a decision

R9 Names are matched without casesrc/app/lib/progress.ts:15 lowercases the name, so "Isaac" and "isaac" share progress. The greeting shows whatever you typed. How to see it: step m8 in section 04.
R10 Reloading always goes back to name entrysrc/app/player/Player.svelte:21 starts with no name, and NameEntry.svelte:6 pre-fills the last one. So a reload in the middle of a module lands on the name screen, then the overview, then Continue. That's what the slice 1 learner check expects. Say if you'd rather skip the name screen when the name is already known.

Not reachable in slice 1, worth knowing

R11 A lone $ or * in lesson text gets misreadsrc/app/lib/math.ts:20 treats text between two $ signs as math, so "costs $5 or $10" would render "5 or " as a formula. math.ts:12 turns 2 * 3 * 4 into italics. The fixture has neither. Lessons Claude drafts in slice 3 might.
R12 The "forgot the square root" wrong answer can't be typedIn content/openintro-sampling/5.1-point-estimates.json, check c4 asks for three decimal places, but its known wrong answer is the range 0.000105 to 0.000106. Someone who forgets the root and rounds to three places types 0.000, which won't match. This only shows up in slice 2, when wrong answers get their own fallback. Today any wrong number gets the same "Not quite".
R13 Answer options need Tab, not the arrow keyssrc/app/player/checks/Select.svelte:14-26 marks the options as a radio group, but arrow keys do nothing. Tab moves through each option, and Space or Enter picks one. Minor, for keyboard users.

Every module, every check answered right

  1. STUDENTPress Start
    Module 1, "What are we estimating?", slides up a little as it fades in. At the top: Overview on the left, 1 / 6 on the right, a thin bar under them. KaTeX: p and p̂ in the reading show as typeset italic math, not as $p$ or \hat{p}.
  2. STUDENTModule 1: pick A point estimate p̂, press Check
    The picked option has an accent border. Check is greyed out until you pick. After Check: green Right., the options lock, Check disappears, and Continue appears.
  3. STUDENTContinue to module 2. Type 0.86, press Enter
    Module 2 shows the formula for p̂ as a centered display fraction. Check stays greyed out while the box is empty or holds letters. Enter works like Check. Then Right. and Continue.
  4. STUDENTModule 3 "Samples vary" has no check. Press Continue. Module 4: type 0.010, Check
    Module 3 shows Continue right away. Module 4 shows the SE formula as a display square root over a fraction. 0.010 and 0.0103 are both Right (the tolerance is 0.0006). The prompt's p = 0.88 and n = 1000 render as math.
  5. STUDENTModule 5: pick It drops to half, Check, Continue. Module 6 "Takeaways": press Finish lesson
    Module 6's button reads Finish lesson, not Continue. After it, you're on the overview: 6 / 6, a full bar, no Start or Continue button, and "You've finished every lesson here. Pick one above to go through it again."

Resume, and a second name

    Amina starts at 0 / 6 with a Start button. Isaac's finished progress doesn't leak in. (While you're here, also try isaac in lowercase: it shows Isaac's 6 / 6, see R9.)

  2. STUDENTUse the browser's Back button twice

  3. STUDENTFrom the overview, press Continue, then Back
    Continue opens the module where you stopped. Back goes to the module before it, not to the overview.
